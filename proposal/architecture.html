Frontend stack

Vue 3 + Vite

Single-page app served by Vite on port 3000. Composition API throughout, with shared state via reactive composables (no Vuex/Pinia).

Backend stack

Python FastAPI

REST API on port 8001. All filtering happens in Python on in-memory data. Pydantic validates all responses. CORS open for local dev.

Data persistence

JSON files (no database)

Seven JSON files in server/data/ loaded into memory at server startup. Changes do not persist across restarts.

i18n

English + Japanese

Two locale files (en.js, ja.js). Locale stored in localStorage. Currency format switches automatically (USD ↔ JPY).

Frontend Architecture

Vue 3 Composition API. Shared filter state is managed by a singleton composable — no external state library needed.

Composables (shared logic)

useFilters.js

Global filter state

Singleton pattern — all views share the same refs. FilterBar writes; views read and watch.

  • selectedPeriod → month param
  • selectedLocation → warehouse param
  • selectedCategory → category param
  • selectedStatus → status param
  • getCurrentFilters() maps state to API params
useI18n.js

Internationalisation

Locale stored in localStorage. Falls back to English if key missing in Japanese.

  • t(key) — translation lookup
  • currentCurrency — USD or JPY
  • translateWarehouse() — city names
  • translateProductName()
  • setLocale('ja') — switches + persists
useAuth.js

User / auth state

Mock auth only — isAuthenticated hardcoded to true. User profile data is static. Not connected to any identity provider.

  • Current user: John Doe / 田中 太郎 (locale-aware)
  • logout() — shows alert, no session logic
  • No roles or permissions

api.js — centralised HTTP client

All HTTP calls go through a single exported api object using axios. Base URL: http://localhost:8001/api. Filters passed as query string params — values of 'all' are omitted.

Data Layer

Seven JSON files in server/data/. All data is loaded into Python memory at server startup via mock_data.py. There is no database — mutations do not persist.

inventory.json
~10 KB · ~50 SKUs

id, sku, name, category, warehouse, quantity_on_hand, reorder_point, unit_cost, location, last_updated. Warehouses: San Francisco, London, Tokyo.

orders.json
~154 KB · 1,000+ orders

id, order_number, customer, items[], status, warehouse, category, order_date, expected_delivery, total_value. Dates: 2025-01 to 2025-12.

demand_forecasts.json
~2 KB · 9 records

id, item_sku, item_name, current_demand, forecasted_demand, trend (increasing/stable/decreasing), period.

backlog_items.json
~1 KB · 4 items

id, order_id, item_sku, item_name, quantity_needed, quantity_available, days_delayed, priority. Represents unfulfillable orders.

spending.json
~3 KB · nested object

Three keys: spending_summary (KPIs), monthly_spending (12 months × 4 cost types), category_spending (4 categories).

transactions.json
~14 KB · 100+ records

id, date, description, category, warehouse, amount, vendor, type. September 2025 transactions.

purchase_orders.json
Empty — []

Schema ready (id, backlog_item_id, supplier_name, quantity, unit_cost, expected_delivery_date, status). Populated when users create POs — not yet persisted.

Constraints & Known Limitations

Items Meridian IT should be aware of for future maintenance and development.

No database — JSON file persistence

All data is loaded from flat JSON files at server startup and held in memory. Mutations (creating purchase orders, adding tasks) are not persisted — a server restart resets all data. Adding a real database (PostgreSQL, SQLite) is the recommended next step before any production use.

Unimplemented mutation endpoints

The frontend API client has methods for tasks (create/delete/toggle) and purchase orders (create/retrieve), and the Pydantic schemas are defined. However, the corresponding FastAPI endpoints do not exist. These calls fail silently in the current UI.

No pagination

orders.json is 154 KB with 1,000+ orders. All records are fetched in a single response on every filter change. For larger datasets this will become a performance problem. Recommend adding offset/limit query params and paginating the orders and transactions endpoints first.

TasksModal.vue still on Options API

One component (TasksModal) was not migrated to Composition API during the previous vendor's work. Functionally it works, but it is inconsistent with the rest of the codebase. Low risk; recommend migrating when the component is next touched.

No authentication

isAuthenticated is hardcoded to true in useAuth.js. All API endpoints are open with no authorization checks. This is appropriate for an internal intranet tool but should be addressed before any external or internet-facing deployment.

CORS open in development

The FastAPI server allows all origins (allow_origins=["*"]). This is intentional for local development but must be restricted to the actual frontend origin before any production deployment.

Hardcoded API base URL

api.js hardcodes http://localhost:8001/api. For deployment to any environment other than a developer's machine, this will need to be replaced with an environment variable (e.g. VITE_API_BASE_URL in a .env file).
